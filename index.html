WHAT IT DOES

From a folder of ROMs to a library your consoles can load.

retroBITE started as the search for a Docker setup to network-load games onto real consoles. When nothing fit, the server script grew into a full collection manager.

02 · IDENTIFY

Every file matched to a title

Scans pick up each console's file types. Files are looked up by name and size first, then by CRC32, MD5 and SHA1. Multi-disc games merge through cue sheets and .m3u playlists. Anything left over waits in Needs identifying, where an exact MD5 match or a name search sorts it out.

03 · METADATA

Artwork, details and ratings

Matched games pull their developer, publisher, genre, players and release date from ScreenScraper, along with up to 23 artwork types in your preferred region, and other regions on request. Each game gets a retroBITE score out of 100, from LaunchBox ratings and how many play it on RetroAchievements, and a rank across your library. Browse each console as a cover grid or a list, filtered by genre, players, rating or status.

06 · NETWORK

Load games over SMB, FTP or PS3NETSRV

Samba (SMBv1 to SMB3) and vsftpd serve the same folders retroBITE manages, so modded consoles and loaders like OPL read games straight off the share, and ps3netsrv streams PS3, PS2 and PS1 games to webMAN MOD. Per-console shares keep paths short, and the dashboard shows each share's address and status.

09 · CONVERSION

Convert and compress, in a queue

Shrink disc images to CHD, CSO or ZSO, pack GameCube and Wii games into RVZ or WBFS, turn PlayStation games into VCDs for POPStarter, or unpack any of them back to ISO or BIN/CUE. Pick one game or a whole shelf, choose the output format, and the conversion queue works through them with the bundled chdman, maxcso, ecm, cue2pops and nodtool. Output can be verified before it reaches your library, and the originals stay until the new file is in place.

10 · DECRYPT

Unlock discs with their key

Some disc images are encrypted and will not start without their disc key. Add the key, typed in or loaded from a key file, and retroBITE checks it against the disc and keeps it with the image. Or decrypt the image for good: the job runs through the same queue as conversion, and the decrypted image replaces the encrypted one. PlayStation 3 is supported today through ps3dec, and more consoles will follow.

Frequently Asked Questions

What is retroBITE?

retroBITE (retrobite.app) is a free, self-hosted collection manager for retro games. It scans your ROM folders, matches each file to a title, adds metadata and artwork, and serves the library to real consoles over your local network.

Which consoles does retroBITE support?

The catalog covers 130+ systems across 55 brands, from the Channel F to the PlayStation 4, plus arcade and engine targets. You add only the consoles you own, and each gets its own folder.

Is retroBITE free and open source?

Yes. retroBITE is free and MIT licensed. The source code will be published with the first public release.

How do games get onto my consoles?

Samba (SMBv1 to SMB3) and FTP shares serve the same folders retroBITE manages, so modded consoles and loaders like Open PS2 Loader read games straight off the network. ps3netsrv streams PS3, PS2 and PS1 games to webMAN MOD on a PS3. Transfer can also copy games to a USB drive or SD card.

Where do metadata and achievements come from?

Metadata and up to 23 artwork types come from ScreenScraper. Each game’s retroBITE score, out of 100, weighs LaunchBox community ratings with how many play it on RetroAchievements. Link a RetroAchievements account to see each game’s achievement set, with new unlocks synced every 15 minutes.

When can I install retroBITE?

Now. retroBITE is in public beta and runs as a Docker Compose stack of three images: the app, the network share and MariaDB. Download the Compose file, set your passwords and your games folder, and start it. The Installation guide covers the command line, Portainer, Dockhand, Synology, QNAP, Unraid and TrueNAS.

Does retroBITE include games?

No. retroBITE manages games you already have and is meant for legally made backups of media you own. It does not include games or endorse piracy.

INSTALL

One Compose file, three images.

retroBITE runs as a Docker Compose stack: the app and the network share, built for amd64 and arm64, with the official MariaDB image. Download the Compose file, change the passwords and point it at your games. There is no key to generate; the first start sets everything up and opens a short setup in the browser.

It runs from the command line, Portainer, Dockhand or a NAS's container manager. The installation guide covers each, and a NAS whose own file sharing already uses the SMB and FTP ports. Join the Discord for help and release news.

For legally made backups of media you own. retroBITE does not endorse piracy. 

mkdir retrobite && cd retrobite

# the stack, and the settings worth changing
curl -LO https://retrobite.app/docker-compose.yml
curl -L -o .env https://raw.githubusercontent.com/retroBITE-app/retroBITE/develop/.env.example

# set AUTH_PASS, DB_PASSWORD, DB_ROOT_PASSWORD, GAMES_PATH
nano .env

docker compose up -d
# then open http://<this machine>:81

# retroBITE: save as docker-compose.yml, then docker compose up -d.
#
# Every setting has a default, so this runs as it is. Change them in a .env
# file beside it, or in your container manager's variables: at least
# AUTH_PASS, DB_PASSWORD, DB_ROOT_PASSWORD and GAMES_PATH. The full list is
# at https://retrobite.app/docs/getting-started/configuration
#
# Needs Docker Compose 2.24 or newer. Runs develop, the newest pre-release;
# set RETROBITE_TAG to a version, such as 20261006-BETA, to stay on one.

services:
  retrobite-web:
    image: retrobite/retrobite:${RETROBITE_TAG:-develop}
    container_name: retrobite-web
    # Anything not listed under environment below — queue workers,
    # ScreenScraper and RetroAchievements timeouts, conversion tools — is read
    # from .env when there is one. See the Configuration docs.
    env_file:
      - path: .env
        required: false
    environment:
      APP_ENV: ${APP_ENV:-production}
      APP_DEBUG: ${APP_DEBUG:-false}
      APP_URL: ${APP_URL:-http://localhost:${WEB_PORT:-81}}
      APP_TIMEZONE: ${APP_TIMEZONE:-UTC}
      # Left empty, a key is generated on first start and kept in the state
      # volume below. It encrypts the passwords retroBITE stores, so set it
      # only to keep one you already have.
      APP_KEY: ${APP_KEY:-}
      LOG_LEVEL: ${LOG_LEVEL:-warning}
      DB_CONNECTION: mariadb
      DB_HOST: retrobite-db
      DB_PORT: 3306
      DB_DATABASE: ${DB_DATABASE:-retrobite}
      DB_USERNAME: ${DB_USERNAME:-retrobite}
      DB_PASSWORD: ${DB_PASSWORD:-retrobite}
      # This machine's LAN address: shown as the address consoles connect to,
      # used to check SMB and FTP are up, and the network Settings →
      # Destinations searches. The web container is behind Docker's bridge and
      # cannot work it out itself.
      HOST_IP: ${HOST_IP:-}
      # The SMB and FTP account, shown on the Network page.
      AUTH_USER: ${AUTH_USER:-retrobite}
      # Transfers write to a USB drive from the browser, which Chrome allows
      # only on https or localhost; a page opened another way links here.
      TRANSFER_LOCALHOST_URL: ${TRANSFER_LOCALHOST_URL:-http://localhost:${WEB_PORT:-81}}
      # nginx is in front, so game files and artwork are sent by it rather
      # than streamed by PHP (App\Support\NginxFile).
      SERVE_WITH_NGINX: "true"
      # Whether retrobite-share runs ps3netsrv, what it serves and to whom,
      # so its card is shown with the right consoles and says when it is open.
      PS3NETSRV: ${PS3NETSRV:-true}
      PS3NETSRV_FOLDERS: ${PS3NETSRV_FOLDERS:-PS3ISO=ps3 PS2ISO=ps2 PSXISO=psx}
      PS3NETSRV_WHITELIST: ${PS3NETSRV_WHITELIST:-}
    ports:
      - "${WEB_PORT:-81}:80"
    volumes:
      # The ROM library, shared with retrobite-share below.
      - ${GAMES_PATH:-./games}:/app/storage/app/games
      # The markdown knowledge base, a folder beside this file.
      - ${DOCS_PATH:-./docs}:/app/storage/app/docs
      # Artwork retroBITE downloads itself, kept out of the games tree so a
      # console browsing the share never sees it.
      - ${MEDIA_PATH:-retrobite-media}:/app/storage/app/media
      # The application key and Reverb's keys. Back it up with the database.
      - ${STATE_PATH:-retrobite-state}:/app/storage/state
    depends_on:
      retrobite-db:
        condition: service_healthy
    restart: unless-stopped

  retrobite-db:
    image: mariadb:11.4
    container_name: retrobite-mariadb
    environment:
      # Read once, when the database is first created: change them before the
      # first start, or change them inside MariaDB afterwards as well.
      MARIADB_DATABASE: ${DB_DATABASE:-retrobite}
      MARIADB_USER: ${DB_USERNAME:-retrobite}
      MARIADB_PASSWORD: ${DB_PASSWORD:-retrobite}
      MARIADB_ROOT_PASSWORD: ${DB_ROOT_PASSWORD:-retrobite}
    volumes:
      - ${DB_PATH:-retrobite-db}:/var/lib/mysql
    # Not published to the host: nothing outside the compose network needs it,
    # and this box sits on a LAN with consoles on it.
    expose:
      - "3306"
    healthcheck:
      # The web container's migrate races the database otherwise: the server
      # reports started long before InnoDB will accept a connection.
      test: ["CMD", "healthcheck.sh", "--connect", "--innodb_initialized"]
      interval: 5s
      timeout: 5s
      retries: 20
      start_period: 30s
    restart: unless-stopped

  retrobite-share:
    image: retrobite/share:${RETROBITE_TAG:-develop}
    container_name: retrobite-share
    env_file:
      - path: .env
        required: false
    environment:
      AUTH_USER: ${AUTH_USER:-retrobite}
      AUTH_PASS: ${AUTH_PASS:-retrobite}
      # Advertised to FTP clients for passive mode. Empty, it is read off the
      # default route on every start.
      HOST_IP: ${HOST_IP:-}
      # The console folders created in the library, and those that also get
      # an SMB share of their own (what Open PS2 Loader connects to).
      GAME_FOLDERS: ${GAME_FOLDERS:-}
      SMB_SHARES: ${SMB_SHARES:-}
      # ps3netsrv on port 38008, serving the PS3, PS2 and PS1 folders to
      # webMAN MOD as its PS3ISO, PS2ISO and PSXISO lists. Read-only, and with
      # no login: the whitelist (such as 192.168.1.*) limits who can read it.
      PS3NETSRV: ${PS3NETSRV:-true}
      PS3NETSRV_WHITELIST: ${PS3NETSRV_WHITELIST:-}
      PS3NETSRV_FOLDERS: ${PS3NETSRV_FOLDERS:-PS3ISO=ps3 PS2ISO=ps2 PSXISO=psx}
    # On the host's network, so consoles find it by NetBIOS and passive FTP
    # works without a port range published. Ports 445, 139, 21 and 38008 must
    # be free: on a NAS they are its own file sharing; see the Installation docs.
    network_mode: host
    volumes:
      - ${GAMES_PATH:-./games}:/games
    cap_add:
      - NET_ADMIN
      - SYS_ADMIN
    init: true
    restart: unless-stopped

volumes:
  retrobite-db:
  retrobite-media:
  retrobite-state:
